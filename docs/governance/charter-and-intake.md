# Project Charter & Intake Standard

**Status:** DRAFT | **Version:** 0.1.0

Define minimum identity, intent, accountability and constraints before execution planning.

## Required charter fields
- Immutable Project ID and display name.
- Sponsor / accountable Project Owner and Project Master / Governance Lead.
- Problem statement, beneficiaries and expected outcomes.
- Measurable success measures.
- In-scope capabilities and explicit non-goals.
- Constraints: budget, dates, stack, vendor, legal, data, staffing and service levels.
- Environments and data classification.
- Risk tier and rationale.
- Canonical Notion, Linear, GitHub and runtime URLs, or explicit NOT_APPLICABLE values.
- PGOS profile version and approved deviations.
- Status, revision, created date and review date.

## Lifecycle
INTAKE → GOVERNANCE_SETUP → READY → ACTIVE → PAUSED / BLOCKED → RELEASE_CANDIDATE → RELEASED → MAINTENANCE → CLOSED

Exceptional states: REJECTED, CANCELLED, ARCHIVED.

A project is READY only when its charter, accountable owner, scope boundaries, risk classification, source map, delivery workflow, minimum security controls and first approved Work Order exist.

## Readiness checklist
- [ ] Owner and decision authority named.
- [ ] Problem, outcomes, metrics, scope and non-goals accepted.
- [ ] Risk and data classification completed.
- [ ] Source-of-truth map completed.
- [ ] Tool access and role assignments verified.
- [ ] Security/privacy baseline selected.
- [ ] First Work Order approved with testable criteria.
- [ ] Verification and release path identified.
- [ ] Known gaps and exceptions recorded.
